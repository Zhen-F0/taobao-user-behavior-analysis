# 文献调研笔记：DIN / Wide&Deep / BST

# 论文一：DIN（Deep Interest Network for CTR Prediction, KDD 2018, 阿里）

## 第1栏 解决什么问题

传统 Embedding&MLP 模型把用户所有历史行为压成一个固定长度向量，无论预测什么候选商品，用户表示都不变，无法体现用户兴趣的多样性和行为的局部相关性。

**（展开：为什么"无论预测什么候选商品，用户表示都不变"？）**

在 DIN 之前，主流做法是把用户的历史行为（比如浏览过的一串商品）各自转成 embedding 向量，然后用一个固定的操作——通常是 sum pooling 或 average pooling，也就是把这些向量直接加起来或取平均——压成一个单一的用户向量。问题就在于这个 pooling 是"无差别"地把所有历史行为揉在一起的，一旦这个用户向量算出来，它就固定了，成了这个用户的"标准画像"。

接下来无论是要预测这个用户对键盘的点击率，还是对奶粉的点击率，模型用的都是同一个揉好的用户向量，只是把它和不同的候选商品向量拼在一起送进 MLP。用户这一侧的表示从头到尾没变过，原因是 sum/average pooling 这个操作天然导致它只能算出一个与候选无关的固定结果。

DIN 觉得这不合理：一个既买母婴用品又买电子产品的用户，你预测他点不点键盘时，他历史里那些奶粉、尿布的行为其实毫无参考价值，却被平均进了用户向量里，稀释了真正相关的电子产品信号。

## 第2栏 核心思想

传统模型里用户表示与候选无关、一次算好，DIN 则让每个候选商品作为"查询"去激活历史行为中与它相关的部分，同一个用户面对不同候选会得到不同的兴趣表示。

## 第3栏 输入特征形态

输入包括用户画像特征、用户行为序列（变长的 goods_id / shop_id / cate_id 序列）、候选广告特征、上下文特征。行为序列里每个 item 做 embedding，候选商品作为"查询"通过注意力和历史行为逐个算相关度、加权得到候选专属的用户兴趣表示。

**（展开："行为序列里每个 item 做 embedding、通过注意力和候选 item 交互"的目的是什么、能达到什么结果？）**

先说 embedding 的目的。商品在数据里是一个个 ID（比如 item_id=232431562），这种 ID 本身是没有数学意义的，两个 ID 数值上接近不代表商品相似。embedding 做的事，是给每个商品学出一个稠密向量（比如 64 维的一串小数），让"语义相似的商品"在向量空间里靠得近——学完之后，两款相似的键盘的向量会比较接近，而键盘和奶粉的向量会离得远。这一步是为了把无意义的 ID 变成可计算、可比较的表示。

再说注意力交互的目的和结果。当候选商品（比如一个键盘）来了，注意力机制会拿它的 embedding 去和用户历史里每一个商品的 embedding 逐个算一个"相关度分数"——历史里那些电子产品会得到高分，奶粉尿布得到低分。然后用这些分数作为权重，对历史行为加权求和。最终的结果是：算出来的用户兴趣向量，会被历史中"和这个键盘相关的行为"主导，无关行为被压低。达到的效果就是——预测键盘点击率时，模型看到的是一个"电子产品偏好被放大、母婴偏好被淡化"的用户表示，判断自然更准。

**（展开：用户历史行为=按时间排的 ID 序列）**

DIN 说的"用户行为序列"，就是——把某个用户的所有行为记录挑出来，按 time 字段从早到晚排好队，然后取出这一串记录的 item_id（或 item_category），得到的这个有先后顺序的 ID 列表，就是 DIN 要的"用户行为序列"。

## 第4栏 模型结构关键设计

DIN 的整体结构可以从下往上分成四层。最底层是 embedding 层，负责把所有稀疏的 ID 类特征（用户画像、历史行为里的商品/类目、候选商品）都转成稠密向量，解决的是"ID 无法直接计算"的问题。往上是这篇论文的核心——activation unit（激活单元）层，它拿候选商品去和每个历史行为算注意力权重，再加权 pooling 得到候选专属的用户兴趣向量，解决的是前面反复说的"用户表示与候选无关"的问题。再往上是全连接（MLP）层，把加权后的用户向量、候选向量、其他特征拼接起来，逐层非线性变换，最后输出一个点击概率，解决的是"把各种特征综合成最终预测"的问题。

除了这三层主干，论文还挂了两个工程性的辅助设计。一个是 Dice 激活函数，它是对 PReLU 的改进，能根据每一批数据的分布自适应地调整激活的分界点，解决的是"固定激活函数不适应数据分布"的问题。另一个是 Mini-batch Aware 正则化，因为工业级数据里稀疏特征动辄上亿维，对全部特征算 L2 正则化算力扛不住，这个设计让每个 mini-batch 只对本批出现过的特征做正则，解决的是"海量稀疏特征正则化的算力开销"问题。

## 第5栏 训练目标与评估

训练目标：DIN 做的是 CTR 预测，也就是判断"用户会不会点击这个广告"，这是一个非黑即白的二分类问题（点=1，不点=0）。训练时用的损失函数是交叉熵，它的作用是衡量"模型预测的点击概率"和"真实是否点击"之间的差距——模型说 90% 会点、结果真点了，损失就小；模型说 90% 会点、结果没点，损失就大。训练就是不断调整参数让这个损失变小。

评估：评估采用 AUC，它衡量的是模型"把正样本排在负样本前面"的能力，值域 0.5（瞎猜）到 1（完美），是 CTR/购买预测这类不平衡二分类任务的标准指标。论文还额外提了 GAUC，是按用户分组算 AUC 再加权平均——因为线上真正关心的是"在每个用户内部，模型能不能把他会点的排前面"，GAUC 更贴近这个业务目标。

## 第6栏 可借鉴点

(1) 可以借鉴这篇文章的输入特征形态，得到每用户时序行为序列特征；
(2) 对 item_id、item_category 做 embedding；
(3) 主结构采用注意力机制动态建模用户兴趣，其权重同时带来可解释性——能看出模型在预测时关注了历史中的哪些行为。
(4) 我们的项目目标变量是"用户未来7天是否购买"，这同样是一个二分类（买=1，不买=0），和 DIN 的 CTR 二分类是同一类问题，因此可以同样采用 DIN 这套"二分类 + 交叉熵损失 + AUC 评估"的框架。

## 第7栏 局限

DIN 依赖足够长的用户历史，对于冷启动用户（行为极少）效果差。

# 论文二：Wide & Deep（Google, DLRS 2016）

## 第1栏 解决什么问题

本文主要解决以往模型无法同时满足 memorization（记住历史中频繁共现的特征组合）和 generalization（推广到未见过的特征组合）这两个技术难点。

## 第2栏 核心思想

模型包含两个主要部分，一个是 Wide 部分（广义线性模型 + 人工交叉特征）负责记忆，另一个是 Deep 部分（前馈 DNN + embedding）负责泛化，两者采用联合训练（梯度同时更新而不是 Stacking 事后融合）。

**（展开：联合训练和 Stacking 事后融合的主要区别是什么？）**

区别在于"两个模型是一起学、还是分开学"。联合训练（joint training）是把 Wide 和 Deep 拼成一个整体，它们共享同一个最终输出和同一个损失函数，训练时一个样本进来，误差会同时反向传播给 Wide 和 Deep 两侧，两边的参数在每一步里同步更新。也就是说，Deep 侧在学习时，是"知道"Wide 侧存在的——它只需要负责补足 Wide 侧没记住的那部分泛化能力，两者边学边分工。

Stacking 事后融合则完全不同：它是先把 LR 训练好、再把 XGBoost 训练好、再把 DIN 训练好，这几个模型各自独立训练、互相不知道对方存在，最后再训一个"融合器"把它们的预测结果综合起来。每个基模型都是在"假设只有自己"的前提下学的。

联合训练因为两侧协同优化，Deep 侧不用重复去记 Wide 已经记住的东西，分工更高效，整体往往更紧凑、参数利用率更高；但它要求你在设计时就把两部分固定进一个网络。Stacking 更灵活——基模型可以是任意异构的（树模型+线性+深度网络都行），各自独立调优。

## 第3栏 输入特征形态

Wide 侧输入原始特征 + 人工叉乘特征（cross-product transformation，如 "AND(gender=female, language=en)"）；Deep 侧把高维稀疏类别特征先 embedding 成稠密向量再进 DNN。

**（展开：为什么 RFM 分、转化率适合走 Wide，类目 embedding 走 Deep？）**

Wide 侧是线性模型，它的强项是"记忆"——直接记住某个特征或特征组合和结果之间的强关联，而且**它擅长处理那种本身就有明确数值含义、和目标近乎单调相关的特征**。RFM 分和转化率正是这种特征：RFM 分高的用户就是更可能购买、转化率高的商品就是更容易被买，这种"值越高、越可能买"的直接、单调的关系，用线性模型一记一个准，不需要复杂变换。把它们放 Wide 侧，等于让模型牢牢记住这些强信号。

Deep 侧擅长的是"泛化"——**处理高维、稀疏、且本身没有数值含义的类别特征**。类目 ID 就是典型：8916 个类目，每个就是个编号，编号之间没有大小关系（类目 100 不比类目 50 "更多"），你没法把它当数值直接喂给线性模型。这种特征必须先 embedding 成稠密向量，让模型自己学出"哪些类目相似"，再由 DNN 去捕捉类目之间复杂的、非线性的关系，并泛化到训练里没见过的类目组合。所以走 Deep。

## 第4栏 模型结构关键设计

模型由并列的两部分组成。Wide 部分是一个广义线性模型，输入原始特征和人工叉乘特征，用 FTRL + L1 正则优化——L1 会把大量无用特征的权重压到 0，产生稀疏解，适合 Wide 侧海量的交叉特征。Deep 部分是一个前馈 DNN，先把高维稀疏类别特征 embedding 成低维稠密向量，再经过若干全连接隐层，用 AdaGrad 优化。两部分的输出（Wide 的线性项 + Deep 的最后一层）加权求和，再过一个 sigmoid 得到最终点击概率，训练时两侧共享这一个输出和损失、梯度同步更新（即联合训练）。

## 第5栏 训练目标与评估

训练目标：Wide&Deep 论文的实验场景是 Google Play 的 app 推荐，它要预测的是"用户会不会安装这个推荐给他的 app"，这又是一个二分类（装=1，不装=0），用的是逻辑损失（logistic loss，本质也是交叉熵）。（点击、安装、购买这类"用户会不会做某个动作"的预测，本质都是同一类问题。）

评估：评估分离线和线上两层。离线用 AUC 等指标看模型排序能力；线上做 A/B 测试——把新模型（Wide&Deep）和旧模型分别部署给两组随机划分的真实用户，在相同周期内比较两组的 app 安装率，以真实业务指标的提升作为最终判据。

## 第6栏 可借鉴点

(1) 本文论证了即使在深度学习时代，人工设计的特征（交叉特征）依然有价值；
(2) 本文揭示了 LR（偏记忆）和深度模型（偏泛化）各有所长，第三周任务中 LR、XGBoost、DIN 分别代表了"记忆"和"泛化"两种能力，对比能够看清在我们的数据上哪种能力更重要。
(3) 本文给了一个工业界真实的 A/B 测试范例——它是怎么分组的、看什么核心指标（安装率）、观察多长时间。在之后写模拟 A/B 方案时，可以借鉴它的思路：分实验组/对照组、定一个核心业务指标、设定实验周期。

## 第7栏 局限

Wide 侧的交叉特征要人工设计，依赖领域经验，不像纯 DNN 那样自动。

**（展开：为什么这是个局限？）**

Wide 侧的威力来自那些人工叉乘特征，比如"性别=女 AND 语言=英文"这种组合。但问题在于，这些有用的组合是人想出来的，不是模型自动发现的。工程师得凭自己对业务的理解，去猜哪些特征组合在一起会对预测有帮助，然后手动把它们造出来喂给 Wide 侧。这就带来两个麻烦：一是严重依赖领域经验，一个不懂电商的人可能根本想不到"周末 AND 母婴类目"这种有价值的组合，模型的上限就被人的经验卡住了；二是组合是爆炸性的，特征两两三三组合起来数量惊人，人不可能穷举，只能挑少数几个，很可能漏掉真正有用的。

对比之下，纯 DNN 的好处就是它能自动从数据里学出特征之间的交互，不需要人一个个手工指定。所以 Wide&Deep 的这个局限本质是：它把"记忆"这部分能力的天花板，交到了人工特征设计的手上。后来很多模型（如 DeepFM、DCN）就是为了解决这个痛点——想办法让模型自动学交叉特征，省掉人工设计。在笔记里点出这个局限，能显示你不只看到了模型的优点，也理解了它的代价。

# 论文三：BST（Behavior Sequence Transformer, 阿里 DLP-KDD 2019）

## 第1栏 解决什么问题

本文主要解决 DIN 捕捉了用户历史与候选的相关性，但并没有捕捉用户点击的先后顺序信息这个问题。

## 第2栏 核心思想

用 Transformer 的 self-attention 层处理用户行为序列，捕捉序列中商品两两之间的依赖关系，再接 MLP 做 CTR 预测。

**（展开：MLP 和 CTR ）**

MLP 是 Multi-Layer Perceptron（多层感知机）的缩写，就是最基础的那种全连接神经网络——若干层神经元，每一层都和下一层全部相连，逐层做加权求和加非线性变换。它在这些模型里的角色是"最后的综合判断器"：前面 Transformer 或注意力层把用户兴趣、商品特征都提取好了，MLP 负责把这些提取好的向量拼在一起，经过几层变换，最终压成一个数值输出。它是深度模型里最常见的收尾结构。

CTR 是 Click-Through Rate（点击率）的缩写，CTR 预测就是预测"用户看到这个商品/广告后点击它的概率"。这是推荐和广告系统里最核心的任务之一——系统要决定把哪些商品排在前面给用户看，靠的就是预测每个商品的 CTR，把预测点击率高的排前面。所以"接 MLP 做 CTR 预测"整句的意思就是：用一个多层全连接网络，把前面提取的特征综合起来，输出一个点击概率。放到你的项目里，你要预测的不是点击而是"未来7天是否购买"，但结构完全一样——最后也是接一个 MLP 输出购买概率。

## 第3栏 输入特征形态

用户行为序列的每个 item 用两类 embedding——序列 item 特征 embedding + 位置 embedding（position embedding，论文用"目标时间 - 该行为时间"的差值来做位置，而非标准位置编码）。候选 item 也拼进序列一起过 Transformer。

BST 和 DIN 虽然模型结构不同（一个用 Transformer、一个用注意力单元），但它们要求的输入数据形态是一样的——都需要"把用户行为按时间排好序的商品 ID 序列"。

## 第4栏 模型结构关键设计

一层 self-attention + 位置编码用时间差，其余接 MLP。

**（展开：为什么是一层 self-attention？）**

BST 论文里做了个实验：他们试了用 1 层、2 层、3 层 self-attention，结果发现 1 层效果最优，多层反而下降。这个结论反直觉的点在于在很多深度学习任务里（尤其是 NLP），Transformer 往往是层数越多、能力越强的，BERT、GPT 都是几十层堆起来的。论文推测是因为用户行为序列不像自然语言那么复杂，一层就足够捕捉依赖，多层反而过拟合。

## 第5栏 训练目标与评估

训练目标：BST 和前两篇一样，做的是 CTR 二分类——预测用户点不点，标签是点击(1)或不点击(0)，用交叉熵损失衡量预测概率和真实标签的差距，训练就是最小化这个损失。（DIN、Wide&Deep、BST 三篇的训练目标本质是同一个模子——二分类 + 交叉熵。这是这一整类"预测用户行为"任务的通用范式。）

评估标准：用 AUC，衡量模型区分正负样本、把会点击的排在前面的能力。BST 论文除了离线 AUC，也在阿里线上做了 A/B 测试并观察到真实提升。

## 第6栏 可借鉴点

(1) 本项目主模型 DIN 未显式建模行为顺序，后续可引入 BST 式的 Transformer 结构捕捉序列的时序依赖，进一步提升效果；
(2) 且由于输入的行为序列特征已具备，迁移成本可控；
(3) 三篇论文与本项目的评估指标一致（均以 AUC 为核心），因此在"用什么指标衡量、如何解读 AUC"上有方法论参照意义；但它们的 AUC 具体数值来自各自的工业级数据集，与我们项目的抽样数据规模和标签定义不同，不宜直接作为目标数值对标。

**（展开：为什么值得作为优化方向？）**

第三周任务主要做的是 DIN，DIN 用注意力捕捉了"哪些历史行为和当前候选相关"，但它没有显式利用行为的先后顺序。而 BST 用 Transformer 的 self-attention 正好补上了这块——它能建模"用户先看了 A 再看 B 再看 C"这种顺序依赖。

## 第7栏 局限

Transformer 计算成本高，序列很长时训练慢。

**（展开：为什么？）**

根源在于 self-attention 的计算方式。self-attention 要让序列里每个元素都和其他所有元素两两算一次相关度——如果序列有 n 个行为，就要算 n×n 次交互，计算量随序列长度的平方增长（复杂度 O(n²)）。序列短的时候（比如几十个行为）这没什么，但一旦用户行为序列很长（几百上千个行为），n² 就会急剧膨胀，计算和内存开销都吃不消，训练自然变慢。

对比一下就更清楚：DIN 的注意力是"候选商品 vs 每个历史行为"，是 1 对 n 的计算，只随 n 线性增长；而 BST 的 self-attention 是"序列内每个行为 vs 每个行为"，是 n 对 n，随 n 平方增长。这就是为什么 BST 更强大（能建模行为间的两两依赖）但也更贵（计算量平方级）。放到项目里，这个局限意味着：如果要用 BST，得考虑对超长序列做截断（比如只取最近 50 个行为），否则训练成本会很高。
